BOUNDED XTIM SOURCE AND RUNTIME AUDIT
====================================

Question
--------
Why can an ideal-correct, independently cheap all-orders A+SX circuit take
roughly163s for an official1e6-shot run while the A-only circuit takes2.7s?
This audit isolates the boundary; it does not claim a proven C++ root cause.

Source evidence
---------------
1. Official tprep/check.py runs exact correctness before noisy sampling.
   Its _sample appends six ideal syndrome MPPs and logical X7/Y7 expectation
   queries, compiles engine='exact', and requests detector, measurement and
   expectation records together. It chunks the official1e8 shots into
   one hundred1e6-shot samplers, with the documented seed sequence.

2. Installed xtim/circuit.py:_CompiledBase constructs _xtim.CompiledProgram
   once. Its _run method calls that compiled program's sample method. Thus
   the observed per-shot cost is not repeated Python parsing or compilation
   for every shot. The staged validator separately measured auto_frame,
   diagnose, exact.verify and noisy sampling and found noisy sampling to
   dominate.

3. Installed xtim/reference.py documents that noise-line placement can
   affect normalization and the terminal reference frame even when noise
   values are zero. It therefore preserves noise structure in cache keys.
   This supports testing physics-equivalent encodings, but does not prove
   any particular encoding will change the sampler's work.

4. quantumn_reaudit/work/lanes/XTIM/REPORT.md records a prior family where
   a carried random q19 MX state selected a slow sampler path; native RX
   with repaired detector frames restored speed. Moving that MX across one
   T gate did not help. Small Bell/MX/T controls did not reproduce the
   effect. The report explicitly labels per-shot framed-plan branching as
   an inference, because its C++ implementation was not available.

5. The installed binary contains framed-sampler, active-block and fallback
   symbols, consistent with that architecture. Symbol names are not a
   proof of which branch ran here. No diagnostic environment switches were
   used to alter the judge and no alternative engine was substituted.

Candidate facts that narrow the explanation
-------------------------------------------
The A+SX ports retain the same fifteen non-Clifford gates (eight T, seven
Tdg). They add only native Clifford SX/SXDG and do not declare a frame.
The official auto-frame is empty, so adding explicit constant-zero FRAME
annotations would not remove a nontrivial frame from the score plan.
The independent reduced-state model's rank remains5.

v31s has last Tdg gates on q10 and q20 at44. For the SX-only port these
move to43; in the A+SX port q10 moves to42. All crossings are idle-only.
Input SX is at44 except q10/q21 at43 in the combined port; inverse SXDG
is at47. The baseline B/C MX pivots are at33, so these random phase records
remain live through the new data Clifford orientation and final readout.

This suggests a representation-dependent noisy-sampling issue involving
the joint data/resource/measurement cone. It does not establish that SX
alone always causes a slow path, nor that every random MX is problematic.
The bounded task did not add an SX-only official timing control.

Two investigated repairs
------------------------
1. Reorder disjoint final-tick measurements. Per-wire ideal and native
   noisy streams were verified identical for both constructions. They pass
   official validity but remain slow, about1.49--1.55s per1e4 shots.

2. Replace the three first-use B/C MX pivots by RX and remove their exact
   detector byproduct terms. This is ideal-correct but changes physical
   initialization noise, so both A-only and A+SX were fully repriced. Their
   losses worsen by1.31e-7 and2.24e-7 respectively. The A+SX sampler remains
   slow at1.375s per1e4 shots. Random pivot frames are therefore not a
   sufficient explanation or repair for this combined candidate.

The root lane additionally tried the equivalent Bell-readout instrument
CX8->9/MX8/M9 versus CX9->8/M8/MX9 with the appropriate record relabeling.
Its short sampler timing also remained slow. The bounded probe was closed.

Rejected shortcuts
------------------
Using H-S-H in place of native SX is not a free same-noise encoding under
STANDARD. It introduces physical gates/ticks unless an actual schedule and
noise-preserving compilation is constructed, and would require full
repricing. Changing xtim engine or cache/fallback environment settings is
not a circuit repair and cannot establish the official submission runtime.

Operational conclusion
----------------------
Retain the physical gain as a research result with an unresolved runtime
constraint. Use the original fast A-only v31s decoder for the current
official run. Its model loss is already below5e-5. This is the strict
conclusion supported by the completed tests; no unmeasured speed fix is
claimed.

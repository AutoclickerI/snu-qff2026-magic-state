2. PHYSICAL SCHEDULE AND CORRECTNESS
-----------------------------------

Data order is [0,20,7,10,3,22,21]. A cells are [1,14,8,9,2,16,15].
All ticks are zero-based. The new gauge consists of one physical SX before
each data qubit's final A interaction and one SXDG at the final tick.
Both layers occupy existing data idle slots. Every gate has native D1(p)
noise; no free physical frame or uncharged basis change is assumed.

v30g:
  Input SX on all data at47; output SXDG on all data at50.
  Move q20 Tdg47->46.

v30g A decoder:
  Input SX on q10/q21 at46, others47; output SXDG50.
  Move q20 Tdg47->46.

v31s:
  Input SX on all data44; output SXDG47.
  Move q10 and q20 Tdg44->43.

v31s A decoder:
  Input SX on q10/q21 at43, others44; output SXDG47.
  The A decoder already moves q10 Tdg44->43. Move it again43->42 for SX.
  Move q20 Tdg44->43.

Every retimed Tdg crosses only a depolarizing idle on that data wire.
Covariance of the one-qubit depolarizing channel makes the retiming itself
noise-channel equal. The physical gauge changes the orientation of the
noisy round relative to the fixed source and resource preparations.

Transversal SX preserves the Steane code space: weight-four Z stabilizers
map to products of corresponding X and Z stabilizers, and X stabilizers
remain X. The ideal detection round acts as identity on that space, so the
inverse SXDG layer restores the target. Staggered SX placements commute
with operations on other data wires. No logical frame is required.

Every built port has ideal acceptance1, ideal loss0 and all six output
stabilizers +1 within numerical roundoff. Harmful-single sums are below
3e-19. All 14 native SX/SXDG D1 channels, nearest-neighbor CXs and unchanged
native depth were checked. These small checks are in *_certificate.json.

The Cedge refinement adds CX28->29 at46, moves the two MZ readouts from46
to47, and XORs c27 into every detector row that contained c26. It retains
the same detector information in a different readout encoding. The added
CX has native D2(p) noise; no new final tick is introduced.

3. BOUNDED RUNTIME CONTROLS
--------------------------

Two final-tick reorderings move B/C measurements before the A8 MX and
retain all output SXDG gates last. They differ in C-before-B versus
B-before-C ordering. Per-wire ideal operations and per-wire native noisy
instruction streams are identical to the original A+SX candidate. The
expected physical loss is consequently unchanged, but the official noisy
sampler remains slow on both. No new loss improvement is attributed to
instruction reordering.

A second bounded test removes carried random phase records from B/C
initialization. The three first-use MX pivots q26/q17/q28 at tick33 become
native RX. Delete c256 from B row18, c260 from rows17/19, and c262 from
row17. Those records occur nowhere else. This preserves the ideal resource
contract but changes initialization noise, so both controls were fully
repriced with actual RX Z_ERROR(p):

Both are worse than their original controls. Reset3 also fails to recover

original candidate on the evidence collected.

4. OFFICIAL VALIDITY PASSES, BUT THE COMBINED SX SAMPLER IS SLOW
--------------------------------------------------------------

The independent validator uses the unmodified official judge with xtim
3.1.3+qff2, qiskit2.5.2 and stim1.16.0. The combined A+SX circuit passes
format, class and exact correctness. Its discovered logical frame is
empty. The official sampler's setup and validity analysis are inexpensive;
the large cost is noisy sampling.

Representative measured timings in the validation environment:
  v31s baseline, 1e6 shots:    2.79002s total, 2.64249s noisy sampling.
  v31s A decoder, 1e6 shots:   2.66917s total, 2.51785s noisy sampling.
  v31s A+SX, 1e4 shots:        2.01614s total, 1.64452s noisy sampling.
  Review5 A+SX, 1e6 shots:   163.30608s total.

The actual review5 1e6-shot SX run passed and returned
L=4.3674424e-5 +/-6.7133e-6, acceptance .526624. Its statistical uncertainty
does not contradict the independent expectation, but its runtime is
unsuitable for the team's normal speed gate. A 1e4-shot run that observes
no logical error is a validity/runtime smoke check, not evidence for
zero expected loss.

Runtime repairs did not remove the slow path:
  C-before-B-before-A8 order: 1.48868s noisy sampling /1e4.
  B-before-C-before-A8 order: 1.55021s noisy sampling /1e4.
  A+SX reset3:               1.37547s noisy sampling /1e4.
The root lane's equivalent Bell-readout representation was also reported
slow, at1.45774s/1e4. The bounded workaround search was then closed.

The original A-only decoder is therefore the practical fast candidate,
at expected L=4.9485457947061475e-5. Its separate official 1e8-shot result
is managed by the validation lane and supersedes the small-shot estimates
when available. The SX family is a demonstrated physical-model gain with
an unresolved execution constraint, not a ready-to-submit recommendation.

5. REPRODUCTION AND NUMERICAL LIMITS
----------------------------------

The sparse evaluator includes all noise orders and all73 required moments.
Reported sparse coefficient omission bounds are about1e-14 for conditional
loss. They do not certify all floating-point roundoff. Official stochastic
scores and their sampling uncertainty must be reported separately.

See README.txt for exact reproduction commands, input snapshots and source
provenance. The best QASM and its original receipts were kept fixed while
runtime diagnostics were generated under separate names. No official
package, judge code, environment switch, gate semantics or noise rule was
modified to obtain these timings.

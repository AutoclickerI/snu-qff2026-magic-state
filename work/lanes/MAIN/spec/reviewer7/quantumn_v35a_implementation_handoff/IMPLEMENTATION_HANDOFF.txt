IMPLEMENTATION AGENT BRIEF — QUANTUMN V35A
=========================================

MISSION
-------
Improve the actual finite-p conditional logical loss under the competition's
current legal/noise/runtime contract. Use the reviewed v35a as a reproducible
anchor, then compare with any newer incumbent found in the implementation
checkout. Produce real candidate circuits and auditable evidence; preserve
negative results that close specific proposals. Ten prioritized methods are
specified in IMPLEMENTATION_TASKS.json and explained in REPORT_EN.txt.

The immediate opportunity is a changed optimization objective: the A decoder
already in v35a changes which preparation faults remain harmful. Reusing old
encoder rankings can discard paths that become preferable under this flag.
The second opportunity is joint physical-check allocation with measured
acceptance costs. Neither currently has a proven whole-circuit winner.

1. FIRST IMPLEMENTATION WAVE
----------------------------
M01 — current-instrument encoder reweighting and path search:
  a. Reproduce current_contract_certificate.json and the flag objective
     certificate before modifying the score function.
  b. Obtain the full EXENC engine and historical ACHECK/EXENC paths, or
     regenerate them. The bundled exenc.py is a source extract, not a complete
     runnable search environment. exact.cpp, DR/prepA_L5_s7307.json and the
     historical path cache are missing from this ZIP.
  c. For the actual current encoder/readout, propagate fault timing, detector
     flips and output errors through the complete accepted instrument. The
     archived v35a local vector is [0,3,4,0,4,0,0,0], total 11 units, with
     4 flag-blind units. This proxy is diagnostic, not the final score.
  d. Reprice available paths first. Keep multiple non-dominated fault-signature
     paths for an identical ideal endpoint. Old scalar endpoint pruning is
     not justified under the changed objective.
  e. Build complete promising circuits on the actual grid/schedule and price
     their full finite-p loss and acceptance. Only then promote to official
     validation. Retain signatures/cache sufficient to reproduce the ranking.

M02 — acceptance-budget compositions, independently of M01 when possible:
  a. Start from the archived physically complete seeds:
     v35a_drop_x20_h19: L=4.419586891482355e-5, A=0.5095889631239797;
     v35a_c_exchange_copies: L=4.4038288902213514e-5, A=0.5036496038577888.
  b. Both are worse than v35a alone. Their loss costs are respectively
     2.605921544027699e-7 and 1.0301214179273433e-7. A new physical check must
     recover more than that cost in the completed composition.
  c. Identify remaining accepted fault mechanisms, then spend recovered
     acceptance on a check that targets them. Compare complete circuits;
     do not sum isolated gains or assume independent acceptance factors.
  d. Preserve all record substitutions. In particular C exchange uses
     old c26 = new c26 XOR c27, removes the helper copies/readouts, and
     leaves the terminal measurement at tick 46.
  e. Avoid the already failed copies-plus-C-edge-at-an-extra-tick candidate.
     Its expected loss is 9.283570894562412e-5, not an improvement.

M10 — bounded wider-record oracle:

2. SECOND IMPLEMENTATION WAVE
-----------------------------
M04: compute a nonlinear selector physically only after a meaningful oracle
headroom result. The legal 8-CX/7-T AND witness establishes expressiveness,
not useful loss. Charge state capture, gates, routing, helper faults and
acceptance; check the complete commuting-axis class.

M05: synthesize required resource correlations by local Cliffords and helper
measurement/vertex minors. The star-to-triangle witness is not a full target
preparation. Resolve byproducts legally and assess correlated faults.

M06: use encoded-resource wires as transient flags for a specific remaining
fault mechanism. Prove the complete joint instrument after conjugating
through changing encoders; a static local echo identity is insufficient.

M07: attempt C-free post-use verification only with an explicit schedule that
controls terminal data exposure. The existing full inverse decoder loses;
an artificially shortened idle diagnostic is not a physical candidate.

M08: start with a syndrome-dressed or jointly fault-tolerant known-state
verifier. The raw late W_L projector is already disproved by correctable
single-qubit errors. A necessary commuting-axis screen is not a full gadget.

M09: build exact-low-stratum plus conditional sampling only for families where
the existing all-orders/cache tools are inadequate. Benchmark variance and
total cost at equal evaluation budget. The proven residual numerator variance
factor does not imply the same speedup for wall-clock time or N/A variance.

Do not launch all architectural branches blindly. Give each an algebraic or
optimistic-oracle gate, then one explicit legal noisy construction. Preserve
the distinction between a local certificate and a completed submission circuit.

3. SHARED SUCCESS AND STOP CRITERIA
----------------------------------
A physical candidate advances only if all applicable stages pass:
  1. Exact intended ideal target on accepted branches, after legal frame but
     BEFORE the judge's final ideal syndrome correction.
  2. Actual permitted instructions, ordered seven-site output, nearest-neighbor
     grid, native schedule, and correct measurement/record/reset semantics.
  3. Correct finite-p numerator and acceptance with ALL inserted physical noise,
     including terminal data idles. Supported sparse candidates require all
     73 moments; a local proxy or a second-order truncation is insufficient.
  4. Expected loss improves the current incumbent under the same model, with
     acceptance satisfying the official threshold and any explicitly retained
     team margin. Compare model with model, not model with a lucky MC draw.
  5. Unchanged official format, class, correctness and acceptance gates pass;
     record runtime and any applicability limits. A small run can check validity;
     finalists need the actual configured final-setting validation.

The sparse cutoff omission estimate (~1.2e-14 for archived circuits) excludes
generic floating roundoff. For extremely small differences, use independent
numerical checks/precision appropriate to the remaining uncertainty. Do not
turn the cutoff number into a blanket interval certificate.

Stop a concrete variant when complete pricing is decisively worse, a rigorous
bound rejects it, a justified optimistic oracle cannot win, or its actual
whole circuit fails a binding rule with no concrete remedy. Do not repeat
large MC runs for a decisively losing expected circuit. A family-wide no-go
claim requires a bound over the family, not just one failed construction.

The official threshold in the reviewed model is A >= 0.5. A0=1, c1=0, zero
logical frame, a 200-CX cap, independent pure blocks, fixed data ownership,
one global stage boundary, and full-grid barriers are not universal rules.
The team's 0.5005 margin and 20 sec/million gate are internal choices. Read
current project policy and justify a change rather than silently relabeling
those choices as contest law. Respect real format, class and runtime limits.

The attached terminal-channel proof gives L >= 1.162e-5 in true expectation
under the inspected STANDARD assumptions. Do not promise sub-1e-5 from a
weaker relaxed lower bound. If a proposed construction appears to cross it,
first locate the exact changed/failed proof assumption and independently
validate the same physical model. A selected MC fluctuation is not a refutation.

4. REPRODUCTION AND EXECUTION PITFALLS
-------------------------------------
Run from the extracted package root in a WORKING COPY. Preserve the original
evidence archive. Python 3.12 / Linux x86_64 is the pinned environment. The
xtim wheel is platform-specific; installation needs network; no wheels or
virtual environment are shipped.

  python3.12 -m venv .venv
  .venv/bin/python -m pip install -r audit/review8_validation/requirements.lock.txt

Receipt check using the archived completed run; no simulator needed:
  python3 check_official_receipt.py \
    audit/review8_validation/v35a.official_100000000_0.json \
    --qasm baseline/v35a.qasm --shots 100000000 --seed 0 \
    --data-qubits 0 20 7 10 3 22 21

    audit/reaudit_evaluation/portable/sparse_walsh.py baseline/v35a 72 canonical

Full official baseline, only when a fresh run is warranted:
  OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 MKL_NUM_THREADS=1 \
    .venv/bin/python audit/review8_validation/run_official.py \
    100000000 0 baseline/v35a \
    b606bd3902d28000e0ee073fc50a7c0870aaa1f2e1ab8947fdb7fd70c762218e

For a short validity check use 1000000 shots and pass that same count to the
receipt checker. Before a fresh run, rename the previous expected receipt
in the working copy or use a never-used candidate stem. Require process exit
code 0 AND a newly generated final receipt. An early failure can occur before
the runner's catch/write block and leave an older passing receipt untouched;
the consistency checker alone cannot distinguish that stale file.

After successful process exit, validate the fresh final receipt. The
runner can return exit code 0 and set finished=true even after a failed gate
or caught exception. Neither is sufficient. Require the intended actual
QASM hash, ordered outputs, judge pin, shots/seed, no exception/parser error,
and format_ok/class_ok/correct_ok/acceptance_ok/passed all true.

The added receipt checker checks schema/consistency and fails closed on a
missing required field. It does not rerun physics, validate source authenticity,
or establish runtime compliance on an unseen server. If the judge schema or
version changes, adapt explicitly rather than bypassing a failed check.

Reprice existing physical seeds with EXPLICIT names:
  OPENBLAS_NUM_THREADS=1 .venv/bin/python \
    audit/review8_architecture/price.py \
    v35a_control v35a_drop_x20_h19 v35a_c_exchange_copies

Never call price.py with no names: it does no work and overwrites
latest_prices.json with an empty list. Builder and certificate scripts can
also overwrite their generated outputs; inspect entry points before running.

Use a unique basename per candidate, even across different folders. Both
the sparse evaluator and official runner may write beside their own scripts
using only the basename. Run distinct layouts in separate processes because
frontend.DATA is module-global. Do not concurrently overwrite shared outputs.

The sparse prototype's validated scope is full barriers, zero references,
diagonal accepted kernels, no FRAME/POSTSELECT directives, at most 20 T
rotations, and ideal acceptance near 1 with ideal loss near 0. A legal design
outside this scope needs an appropriate evaluator extension or the actual
official pipeline. Its result cannot be trusted merely because the script
returns a number; unsupported does not mean forbidden by the contest.
